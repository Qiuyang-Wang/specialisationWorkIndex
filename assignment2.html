Spatial Input Interaction

My first area of exploration is Spatial Input Interaction. It focuses on how Player A and Player B can jointly influence the same sound system through different inputs. Player A uses the A, S, D and F keys to trigger short sounds, whilst Player B uses the Spatial Field to alter stereo panning, filter frequency and stability. The three prototypes maintain essentially the same sound mapping, moving targets and shared state, altering only Player B’s method of input. This approach was inspired by the MDN Violent Theremin, which maps mouse movements to sound parameters in real time. MDN’s spatial audio / PannerNode example further provides a reference for the concept of ‘spatial position corresponding to sound position’.

Prototype 1: Hover Control

Prototype 1 utilises continuous hovering. Once the mouse enters the Spatial Field, `mousemove` continuously reads the X/Y coordinates, allowing Player B to alter the sound without clicking. This version directly follows the real-time mouse tracking approach of the MDN Violent Theremin and is also used to test how continuous input affects the sounds triggered by Player A. The Sync Point remains fixed, with only the colour and status text changing, so that the primary variables are centred on the input method.

Prototype 2: Click Position Input

Prototype 2 utilises a single click. The system only records a new position upon clicking, and the red dot remains in that position until the next input. This transforms the task of continuous mouse tracking into a single-point selection by the user within the space, allowing Player B to first set a state and then observe the subsequent changes in the moving target, the Shared State and the sound. The sound mapping remains consistent with 1A; therefore, the primary comparison is the timing and method of input.

Prototype 3: Click and Drag

Prototype 3 utilises click-and-drag. Player B can only continuously update the position whilst holding down the red dot; upon releasing, the current state is retained. This version draws on the drag structure from the classroom example—mousedown → mousemove → mouseup—combining continuous tracking with active manipulation. It was used to explore how a player, when explicitly ‘grabbing and moving’ a state, could continuously influence the shared audio outcome for both players.

Shared State Visual Feedback

My second area of exploration was Shared State Visual Feedback. All three prototypes utilised the same hover input, sound mapping, movement targets and stability calculations, with only the visual representation of the central Sync Point altered. This direction builds upon my earlier exploration of shared state in Assignment 1 and was also inspired by Inter-symmetric Sequencer 01. This multi-player music system allows different participants to observe changes to the same shared interface. The real-time visual and audio feedback in BeatCombo also provided a reference for real-time state representation.

Prototype 4: Expanding Core

Prototype 4 uses the size of a circle to represent stability. The closer Player B gets to the target, the larger the central red circle becomes; as the distance increases, it shrinks. This design stems from my earlier concept of an expanding central core, which directly translates numerical values into size. As the centre of the circle and the display area remain fixed, the visual changes are concentrated primarily on the size itself, allowing us to test whether players can quickly discern the direction of change in the current state.

Prototype 5: Circular Progress Ring

Prototype 5 utilises a Circular Progress Ring. As stability increases, the ring fills in a clockwise direction whilst the pointer rotates; when the value decreases, both retreat. This version borrows the visual structure of a common progress indicator, converting stability into a proportional change within a fixed range. It is used to observe whether players can, through the ring’s completion level, more directly understand what is required to maintain the shared state.

Prototype 6: Waveform / Pulse Feedback

Prototype 2C transforms stability into a dynamic waveform. When stability is low, the amplitude of the waveform and its subtle fluctuations increase; as the value rises, the waveform gradually stabilises. This approach builds on my earlier idea of representing ‘unstable states’ as tremors in the waveform, whilst linking visual movement to the roughness of the sound. It is used to test whether players can quickly grasp the current state through dynamic characteristics, rather than size or progress proportion.
