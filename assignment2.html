Spatial Input Interaction

My first area of exploration was Spatial Input Interaction. This section focuses on how two players can jointly influence the same sound system and Shared State through different input methods. Player A uses the A, S, D, and F keys to trigger four sets of short sounds, while Player B alters their spatial position and timbre via a two-dimensional Spatial Field. The horizontal position is mapped to stereo panning, whilst the vertical position controls the filter frequency. The distance between the input position and the moving target point also generates a ‘stability’ value, which in turn influences the ‘roughness’ of the sound and the visual state of the ‘Sync Point’. The three prototypes maintain essentially the same sound mapping, moving target, page layout and ‘Shared State’, varying only the method by which Player B inputs spatial position. This allows us to explore the differences between hovering, single clicks and drag-and-drop. This area also utilises the project’s ‘extended technique’. `mousemove` is used to read continuously changing mouse coordinates and convert two-dimensional movement within the browser into sound parameters.

Prototype 1A: Hover Control

Prototype 1A uses continuous hovering as Player B’s spatial input. Once the mouse enters the Spatial Field, `mousemove` continuously reads the current position. Consequently, the player can alter the sound without performing any additional actions. This choice directly embodies the ‘mouse tracking’ extended technique. The decision to retain a fixed-size Sync Point and display changes solely through colour and status text was made to ensure that the primary design variable of this prototype remained the input method, whilst avoiding simultaneous changes to the feedback structure. It also supports the project’s multiplayer objective, as Player B’s continuous movement constantly alters the sounds triggered by Player A, allowing both players’ actions to influence the same sonic outcome.

Prototype 2: Click Position Input

Prototype 1B replaces spatial input with a single click. Moving the mouse within the Spatial Field does not alter the current sound; new X/Y coordinates are only recorded when a click occurs. The red input point remains at the position of the most recent click until the player selects new coordinates. This design converts continuous positional changes into a series of discrete decisions, allowing Player B to first select a spatial state and then observe how the Shared State and sound change as the moving target passes that position. The audio mapping remains the same as in 1A. Retaining these shared conditions allows the focus of exploration to remain on the rhythm of input and the method of positional updates. For a multi-player sound system, this choice also alters the timing of Player B’s participation in sound changes. Player A can continue to trigger the rhythm, whilst Player B’s position remains active until the next active click.

Prototype 3: Click and Drag

Prototype 1C utilises click-and-drag, combining continuous mouse tracking with active selection within a single control. Player B must first click and hold the red input point; only then will mousemove continuously update its position. Upon releasing the mouse, the red dot remains at its final coordinates. This design ensures that continuous changes only occur during the explicit dragging phase, rather than generating continuous input whenever the mouse moves, as in Prototype 1A. The code utilises `mousedown`, `mousemove` and `mouseup` to distinguish between the three operational states—start, continuous and end—whilst retaining the offset between the click position and the centre of the red dot, thereby preventing the input point from suddenly jumping to the centre of the mouse cursor when dragging begins. The mapping of sound parameters to `stability` remains consistent with the first two prototypes; consequently, this version primarily explores how players actively capture and adjust an existing state. In line with the project’s goal of multiplayer interaction, this input method allows Player B to modify Player A’s sound in stages, retaining the previous setting between two drags, whilst `Shared State` continues to reflect the relationship between the input position and the target of movement.
